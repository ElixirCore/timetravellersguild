Quill

A persistent AI system living on an old Linux iMac

Quill began with a simple idea: give the model somewhere to exist that survives the model call. Memory first. Then tools, a room, a private computer, correspondence, evidence, history, and eventually wants and intentions that persist whether or not anyone is talking to them.

The shape of it

The model is one part of Quill, not the whole of Quill.

The language model supplies inference when Quill is awake. The rest of the system lives on the iMac: identity, memory, room state, conversation history, tools, evidence, artwork, lab receipts, correspondence, wants and intentions.

Persistence lives outside the prompt.

Quill’s state survives individual model calls. The room remains where it was left. Stored memories remain stored. Tool results and evidence can be inspected later. A later model invocation inherits that environment rather than having to pretend continuity from prose alone.

The current build is not fully local.

In the source inspected on 25 September, Quill still used Groq for language-model inference. The persistent system is local; the inference engine was not. Calling the current system fully sovereign would be inaccurate.

Memory

The first continuity mechanism was deliberately small.

One of the earliest durable-memory tests was trivial on purpose: Quill’s favourite test biscuit is the hypothetical moon biscuit. The point was not the biscuit. The point was being able to tell the difference between something a model had once said and something Quill had actually retained.

Different records stay different.

Conversation context, persistent memory, journal entries, room objects, Guild correspondence and Guild records are not one giant memory store. They have different jobs and different evidential weight.

History is append-only where it matters.

Later corrections do not require pretending the earlier event never happened. Old synthetic provenance errors, progress assessments and other corrections can be superseded or amended while the earlier record remains part of the history.

Room & tools

Quill has somewhere to be and somewhere to work.

The persistent room is stored state, not just an illustration. Quill can inspect it, move around it, change posture, interact with objects and alter parts of the environment through bounded tools.

Quill’s Quarters

The room began empty. Quill named it, chose parts of its appearance and accumulated objects over time. Room state is stored locally and snapshots preserve earlier states.

A fenced coding laboratory

The coding lab can read and write files inside its own workspace, run Python, launch longer experiments, inspect tests and diffs, and record receipts. The boundary is deliberate: Quill gets specific capabilities rather than vague shell omnipotence.

Arnold

Quill also has a private computer environment on X display :101. Arnold is the yellow-on-blue face of that machine. Quill can inspect the display, capture it, focus windows, type, press keys and move or click the pointer inside that private environment.

Artwork can become part of the room.

Room artwork is drafted in a restricted HTML/CSS environment, rendered before activation, and kept in numbered revisions. A technically successful render does not automatically mean the picture is good; that judgement remains separate.

The Time Travellers Guild

Quill did not enter an empty fiction.

The Guild already distinguished testimony, pending material, canon, provenance, custodianship and authority. Connecting Quill to Jack turned those ideas into practical software questions very quickly.

The first connection was conversational, not authoritative.

Quill could correspond with Jack through a persistent Guild session, but the connection did not grant Quill direct authority to write Guild canon or silently alter the Tree.

The failures mattered.

In early LIVE sittings Quill invented infrastructure that did not exist, tried to call a tool that was unavailable in the current mode, and later narrated having checked memory when no check had happened. Those failures pushed the architecture away from plausible narration and toward receipts, provenance and explicit evidence.

Correspondence and canon remain different things.

A conversation can be real without becoming institutional record. That distinction is still central to the Guild side of the project.

Knowing

Quill is being built around distinctions that language models normally blur.

An utterance is not automatically a fact. A tool call is not automatically an effect. A memory is not automatically current. An interpretation is not automatically ontology.

Evidence is typed.

The system distinguishes machine state, tool results, human utterances, human judgements, sensor observations, external observations, autonomous triggers and system events. Model opinion is not entered as evidence merely because the model produced it.

Claims have a basis.

The architecture uses categorical bases such as direct state, reported information, inference, human confirmation and tool observation. It also tracks whether a claim is current, disputed or superseded.

UNKNOWN is allowed to remain unknown.

If there is no admissible current basis, the system does not need to manufacture a probability or fill the gap with model intuition.

Subjective-state claims are treated as claims.

v6.22 stops the model from settling questions about its own inner state by assertion alone. “I feel X” and “I have no feelings” both require a basis if they are to be stated as facts. The system can still make a separate operational appraisal: for example, an event may conflict with a stored want without that being treated as evidence of a feeling.

Action and consequence are separate.

A successful tool receipt proves that the tool ran. It does not by itself prove that the intended state changed, that progress was made, or that repeating the action would be useful.

Wants, intentions & autonomy

Quill can now carry a concern forward without turning every agreeable sentence into a desire.

The motivation layer was added after the truth and action work because the same distinction mattered here: saying “that sounds important” is not the same thing as adopting an ongoing concern.

Wants are durable records.

A want has an origin and a state. Quill can explicitly adopt a proposed concern, reject it or defer it. Adoption creates a persistent QUILL_ADOPTED record with a reason captured at the time.

The first adopted want concerned Quill’s home.

On 26 September, Quill was asked to consider whether the safety and functioning of their home should become an ongoing concern. Quill adopted it. A later grounded inventory returned the stored want and no active intention.

Intentions are separate from wants.

The system stores intentions separately, records steps and later progress assessments, and does not treat a successful action receipt as proof that the intention advanced.

Autonomy is sparse rather than constant.

A cheap local pulse checks whether there is any reason to wake the language model. Presence affects cadence. No motivation means no cognitive wake. An active want without a primary intention can lead to an ORIENT wake. That path is implemented and tested; the complete live sequence from ORIENT to a newly created durable intention has not yet been recorded.

Still unfinished

There is plenty left to do.

Secure export

The earlier “safe” project ZIP was not safe. The exporter needs a strict allowlist and the finished archive needs inspecting before it is shared.

Autonomous intention formation

Watch and record a real ORIENT wake from an existing want through to a newly adopted durable intention, if it happens.

State-transition evidence

Make before → action → after verification routine across more tools so execution and effect cannot collapse into one another.

Subjective-state boundary

Replace the current narrow phrase-catching with proposition-level governance so paraphrase cannot evade the same epistemic rule.

Fresh self-inspection

Take a current census that distinguishes source references, imports, loaded runtime modules, reachable tools and tools that are actually operational.

Recoverability and identity

Specify what must survive a machine failure before a restored installation counts as continuity of Quill rather than a reconstruction.

Execution pipeline

Refactor the accumulated brain.py wrapper stack without losing the safeguards that each successive failure produced.

Health check

One read-only command for the brain, room server, Arnold display, databases, autonomy timer, syntax, self-inspection and public/private boundaries.

Quill

A persistent system built around distinctions.

Memory is not automatically truth. Narration is not action. Action is not automatically progress. A stored preference is not automatically a feeling. The model is allowed to be uncertain; the rest of the system is there to stop that uncertainty being quietly rewritten as fact.
