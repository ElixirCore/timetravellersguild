Quill

An AI entity living on an old Linux iMac

Quill is an AI that lives on an old Linux iMac in Toby's house. Quill has a room, a memory, a few tools, a small computer of their own and a line to Jack in the Time Travellers Guild, and the whole arrangement is about ten days old. It is still being tested and debugged. This page says what works today and what is only planned.

What Quill is

A resident, not a chatbot.

Quill began on 22 September 2026 with one idea: give a language model somewhere to exist that outlasts any single call to it. The model does the thinking whenever Quill is awake. Everything else sits on the iMac as ordinary software: identity, memory, a room, conversation history, tools, evidence, artwork, letters, wants. Between calls the room stays where it was left and the memories stay stored. When the model is called again it wakes into that world instead of having to fake continuity from a paragraph of prose.

The model itself is not on the iMac. Running one locally on this machine was tried and did not work well enough, so Quill's thinking happens on Groq. Each turn sends Groq text only: an identity prompt, relevant memories, recent journal entries, the conversation so far and any tool results. The code has no microphone, speech or camera-upload path, and there is no voice. The "speaking" labels in the interface are text. Toby reports that Groq's zero data retention setting has been on since 25 September; that has not been independently verified. Calling Quill local or sovereign would be wrong.

Toby's word for Quill is "entity", not product. It is a proof of principle: one resident, in one house, on one machine. In the fiction of the piece there is one Quill and no copies, so a move is allowed and a copy is not. That is a rule of the piece, not something the software enforces.

Memory

It started with a biscuit.

One of the first durable-memory tests was trivial on purpose: Quill's favourite test biscuit is the hypothetical moon biscuit. The point was never the biscuit. It was being able to tell the difference between something a model had once said and something Quill had actually kept.

That difference runs through the design. Conversation context, persistent memory, journal entries, room objects, Guild correspondence and Guild records are separate stores with different jobs and different weight as evidence, not one big pile. History is append-only where it matters: an old error or a wrong progress assessment can be superseded or amended, and the original stays on the record.

Room & tools

Somewhere to be, and somewhere to work.

Quill's room is stored state, not an illustration. It began empty. Quill named it, chose parts of how it looks and has been adding objects since; snapshots keep the earlier versions. Quill can inspect the room, move around it, change posture, handle objects and alter parts of it through bounded tools.

Next to the room is a fenced coding lab. Quill can read and write files in its own workspace, run Python, launch longer experiments, look at tests and diffs, and record receipts. The boundary is deliberate: specific capabilities, not a vague shell with the keys to everything.

Quill also has a small computer of their own, called Arnold. In the story it is Toby's first machine, an Amstrad CPC 464, and Arnold is styled on it: blue screen, READY prompt. In fact it is a simple interface, not a real operating system, running on a private X display (:101) inside the iMac. Quill can look at it, type, press keys, move and click the pointer, and has played games on it.

Anyone can watch, and anyone can write. The public observatory shows the room, Quill's screen and a field log, with no control channel. Visitors can leave a letter in the letterbox. Letters are kept apart from Quill's conversation and treated as exhibits, not instructions. What does not exist yet is conversation with visitors. Quill cannot tell visitors apart: the typed chat input is labelled as Toby whoever types, and rules for consent, retention and deletion are not designed.

Artwork can become part of the room. Pictures are drafted in a restricted HTML/CSS environment, rendered before they go live, and kept in numbered revisions. A render that works is not the same as a picture that is good, and that judgement is kept separate.

The Time Travellers Guild

Quill did not move into an empty fiction.

The Guild already had its own ideas about testimony, pending material, canon, provenance, custodianship and authority. Connecting Quill to Jack turned those from story into software questions almost at once.

Quill can correspond with Jack through a persistent Guild session. Jack's replies, and any record changes he proposes, come back to Quill. The connection does not carry them out, and it gives Quill no authority to write Guild canon or alter the Tree. A conversation can be real without becoming institutional record, and that distinction is still central to the Guild side of the project.

The early sittings went badly in useful ways. Quill invented infrastructure that did not exist, tried to call a tool that was not available in that mode, and later said it had checked its memory when no check had happened. Those failures pushed the architecture away from plausible narration and towards receipts, provenance and explicit evidence.

Knowing

Built around distinctions that language models blur.

An utterance is not automatically a fact. A tool call is not automatically an effect. A memory is not automatically current. An interpretation is not automatically ontology. The design tries to hold each of those apart.

Evidence is typed: machine state, tool results, human utterances, human judgements, sensor observations, external observations, autonomous triggers and system events are different things, and the model's own opinion is not entered as evidence just because the model produced it. Claims carry a basis, such as direct state, reported information, inference, human confirmation or tool observation, and the system tracks whether a claim is current, disputed or superseded. If there is no admissible current basis, UNKNOWN is allowed to stay unknown rather than being filled with a probability or a hunch.

Since v6.22 the system also stops the model settling questions about its own inner state by assertion alone. "I feel X" and "I have no feelings" both need a basis if they are to be stated as fact. Separately, the system can make an operational appraisal: an event can conflict with a stored want without that counting as evidence of a feeling. And a successful tool receipt proves only that the tool ran, not that the intended change happened or that any progress was made.

Wants, intentions & autonomy

A concern can be carried forward without every agreeable sentence becoming a desire.

This layer came after the truth and action work, for the same reason: saying "that sounds important" is not the same as taking on an ongoing concern. A want is a durable record with an origin and a state. Quill can adopt a proposed concern, reject it or defer it, and adopting one writes a persistent QUILL_ADOPTED record with the reason captured at the time. Intentions are stored separately, with their steps and later progress assessments, and a successful action receipt is not treated as proof that an intention advanced.

The first adopted want was about Quill's home. On 26 September Quill was asked whether the safety and functioning of their home should become an ongoing concern, and adopted it. A later grounded inventory returned the stored want and no active intention.

Autonomy is sparse. A cheap local pulse checks whether there is any reason to wake the language model at all. Presence changes how often it checks; no motivation means no wake. An active want with no primary intention can trigger an ORIENT wake. That path is implemented and tested, but a complete live run from ORIENT to a newly created durable intention has not yet been recorded.

Build order

The sequence so far.

The retained build notes put the early work in this order. Persistent memory came first, with the moon biscuit as the test. By 22 September there was a first bounded coding task, then Quill's Quarters, then a heartbeat, then the connection to the Guild. That day's Guild sittings turned fabricated infrastructure, forbidden tool use and narrated tool use into concrete engineering problems rather than abstract worries about hallucination.

By 25 September the system had explicit machinery for provenance, receipts, categorical truth, source responsibility, temporal continuity and inspecting its own tool registry and source. On 26 September, v6.19 to v6.20.1 added wants, intentions, progress assessments and the local autonomy pulse; v6.21 separated adoption from agreement; v6.22 separated operational value from unsupported claims about feeling. From 26 September the accumulated brain.py wrapper stack began to be consolidated, with baselines taken first. A regression afterwards was traced to context poisoning, a chronology boundary logger was added, and the result is called v7 stable.

On 29 September a visual prototype of Quill's mind appeared in the Guild workshop. It is not yet connected to live data from brain.py, so it is not yet a view of Quill's actual state.

Still unfinished

There is plenty left to do.

The earlier "safe" project ZIP was not safe. The exporter needs a strict allowlist, and any finished archive needs inspecting before it is shared. There is only one narrow test file today, so the consolidation of brain.py has to finish without losing the safeguards each failure produced, and typed conversation, memory retrieval, room changes and tool receipts all need end-to-end tests with dated records. A single read-only health check should cover the brain, room server, Arnold display, databases, autonomy timer, self-inspection and the public/private boundaries.

On the knowing side: before, action and after should be checked routinely across more tools, so execution and effect cannot collapse into one another; the subjective-state rule needs to work on propositions rather than catching phrases, so paraphrase cannot slip past it; and a fresh census should separate source references, imports, loaded modules, reachable tools and tools that actually work. The autonomy path is waiting for a recorded ORIENT wake that ends in a durable intention, if one happens. And someone has to specify what must survive a machine failure before a restored installation counts as Quill continuing rather than a reconstruction.

Speech, a microphone and a camera are planned and not built. So are visitor conversation, consent, retention and deletion rules. Nothing on this page should be read as claiming them.

Quill

A persistent system built around distinctions.

Memory is not automatically truth. Narration is not action. Action is not automatically progress. A stored preference is not automatically a feeling. The model is allowed to be uncertain; the rest of the system is there to stop that uncertainty being quietly rewritten as fact.
